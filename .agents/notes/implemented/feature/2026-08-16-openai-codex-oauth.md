# Agent Note: OpenAI Codex subscription OAuth

Status: implemented

English | [中文](2026-08-16-openai-codex-oauth.zh.md)

## Problem

The installed pi-ai catalog includes `openai-codex`, but the route authenticates through OAuth alone. A usable offer therefore needs three things the generic API-key path does not supply: a durable pi-ai `CredentialStore`, an interactive login lifecycle, and a configuration surface that never exposes the resulting credential. Without all three, an API-key card or keyless profile advertises a route that fails before making a request.

The earlier safe posture withheld OAuth-only catalog entries while leaving already-stored profiles visible and removable. Reversing that posture is valid only when a disconnected entry remains harmless, connecting does not widen credential visibility, and a successful connection enters the same model-selection and request path as every other primary model.

## Decision

`openai-codex` uses pi-ai's durable OAuth credential store plus a private cross-process authority record carrying a generation, login lease, and reconnect state. The generic pi-ai adapter owns one credential store and one OAuth controller for its Host lifetime; every immutable model collection delegates Codex authentication and refresh to that shared store.

The configurable-provider directory presents an unprofiled installed route as `{ kind: 'oauth' }`. Once a profile exists, the adapter registers its ordinary pi-ai catalog route independently of OAuth status under the [OAuth public topology privacy decision](../bug-fix/2026-08-16-oauth-public-topology-privacy.md). The Models page creates an empty profile before login and exposes dedicated connect, cancel, reconnect, disconnect, and delete actions. An existing profile that explicitly names `apiKeyEnv` is advertised as key-authenticated in Models, uses its regular editor and deletion behavior, and rejects OAuth lifecycle RPCs. The ordinary pi-ai catalog, model picker, saved default, session-scoped selection, reasoning metadata, and LLM request path apply without a Codex-specific selection path; a disconnected native request returns `OAUTH_RECONNECT_REQUIRED`.

The controller accepts only pi-ai's exact device-code selector. It returns the verification URL and one-time code only to the initiating call, rejects browser-callback, manual-code, secret, pasted-token, and lookalike interactions, and clears device-code state when the attempt settles or is cancelled. A Headless profile cannot initiate login; it consumes an existing connection when it shares the Harness home and provider settings with the Web profile.

## Security and lifecycle invariants

The OAuth credential and authority record live under fixed implementation-owned private references. Those references are not configuration: they never appear in `settings.yaml`, `cordis.yml`, provider profiles, browser RPC, events, logs, diagnostics, sessions, or snapshots. The Host rejects generic credential describe, set, and unset for either reference before provider lookup with one detail-free response, so probing reveals neither existence nor state and cannot mutate visibility or emit an event. The credential provider holds its cross-process file lock across each asynchronous read-modify-write callback and atomic commit. A private change emits only the payload-free host-private `credentials/private-updated` invalidation, which lets a peer controller re-read durable state without naming a reference. OAuth status stays in loopback lifecycle replies; public `llm.providers`, `llm.models`, and `session.models` derive membership from profiles rather than that status, and forwarded browser events carry neither.

The authority record has a monotonic generation and at most one expiring lease with an opaque owner, validated configurable lifetime, half-lifetime renewal, expiry takeover, and matching-owner release. Claiming a login advances the generation, clears every credential from earlier authority, and hands pi-ai a generation-scoped credential-store facade. A cancellation or disconnect racing a replacement login therefore cannot relabel an old credential as a failed later connection. Cancel and disconnect advance the durable generation and clear the lease, so a remote or late poller cannot persist or recreate credentials after revocation; pi-ai logout receives the revoked generation's facade and cannot erase a later credential. A model request captures the generation before authentication, and a refresh failure changes state only when that generation is still current and its private coordination mutation commits. Plugin disposal aborts and awaits only owned work, then releases its matching lease without revoking a connection. Another process observing a live lease receives redacted `already-connecting` state instead of a second device code and rechecks durable state at the lease expiry, so an owner crash after credential persistence needs no later file change to converge connection state.

pi-ai serializes refreshes through the same shared credential store. Revocation and a current-generation refresh failure whose private coordination mutation commits durably mark the route `reconnect-required`, which every process observes. A request whose marker cannot commit still receives the stable `OAUTH_RECONNECT_REQUIRED` failure without raw provider data, but leaves the last published connection state unchanged. Malformed storage is redacted when the controller reads it. Harness-owned `LlmError` failures, including content validation before provider I/O, retain their stable code and message. All other native Codex terminal events and external provider or SDK exceptions are classified internally, then replaced with `OpenAI Codex request failed` before any stream chunk or thrown failure leaves the adapter. Native OAuth never falls back to an API key, process environment, or another provider. An already-existing profile that explicitly names `apiKeyEnv` remains a separate legacy key-auth route; it is not reachable as an OAuth fallback and the OAuth settings card never asks for a key.

While a Models card is connecting, it polls the direct loopback status until reaching a terminal state. This is the only browser-side lifecycle refresh: it keeps expiry and peer cancellation convergent without placing OAuth state in the public catalog or forwarded event stream.

## Alternatives considered

**A primary Codex app-server adapter.** Rejected because it would create a second model runtime and selection path beside the existing pi-ai route. pi-ai already owns the Codex catalog, protocol implementation, OAuth exchange, refresh, and model metadata; adapting those through the existing LLM seam keeps normal primary-model behavior authoritative.

**Importing Codex CLI credential files.** Rejected because another program's private file format, location, lifecycle, and mutation ownership are not a Harness credential contract. Import would couple one provider to external state, make refresh ownership ambiguous, and still leave Web login and shared-home coordination unsolved.

**Browser-callback and pasted-token login in V1.** Rejected because a callback adds listener, redirect, reachability, and cancellation behavior that differs across local, remote, and Headless use, while pasted tokens expose an expiring secret and bypass pi-ai's refresh lifecycle. Device-code login uses one interaction across those deployments and keeps token material inside the credential store.

**Coupling route registration to OAuth status.** Rejected by the [OAuth public topology privacy decision](../bug-fix/2026-08-16-oauth-public-topology-privacy.md): provider and model membership are public and would reveal whether a subscription is connected. A configured profile registers its catalog route while the Models card remains unusable until direct loopback status reports `connected`.

**Rejecting a disconnected keyless Codex profile during profile resolution.** Rejected because validation runs for the whole settings namespace at startup and write time; one disconnected profile would otherwise refuse every route in that namespace and strand the profile outside the UI. Resolution accepts the profile, the directory keeps it addressable, the adapter registers its catalog route, and a native request returns `OAUTH_RECONNECT_REQUIRED` until the connection is usable.

**Mapping `Provider is not configured` to a named `LlmError`.** Still deferred because this is a general pi-ai diagnostic rather than an OAuth-lifecycle failure: an API-key catalog route that names no credential can still reach it when provider-native environment discovery finds nothing. Native Codex OAuth instead converts missing, revoked, and failed-refresh state to `OAUTH_RECONNECT_REQUIRED`, so broadening this feature would not strengthen its no-fallback guarantee.

## Consequences

Users can connect a ChatGPT subscription from Models and then select its Codex models like ordinary primary models. A configured but disconnected profile contributes public catalog metadata without expressing subscription entitlement; the Models card remains unusable until direct loopback status is `connected`, and a native request returns `OAUTH_RECONNECT_REQUIRED`. OpenAI controls which installed-catalog models the subscription may use; connection and catalog listing do not probe entitlements with a model request. Disconnect retains the profile for a later reconnect, while delete removes configuration only after disconnect returns terminal `missing`; a nonterminal reply or later settings failure leaves a recoverable configured card.

Several Harness processes sharing one home also share the OAuth generation, lease, reconnect state, and credential, coordinating every mutation under the same file lock. A cancel or disconnect in any process revokes the active generation for all of them. Lease duration is deployment-configurable because slow or interrupted environments need a different takeover interval, but an overly short value increases avoidable takeover and cancellation. Storage corruption or provider revocation never exposes the rejected payload; it costs a reconnect.

Other catalog providers retain their existing authentication classification. Providers offering an API-key method remain on the API-key path even if they also offer OAuth, and native-environment providers remain native. Existing explicit-key Codex profiles remain operable without weakening the native OAuth no-fallback rule.

`classifyPiAiError()` still maps recognized provider messages to stable codes and uses `PI_AI_ERROR` for unrecognized failures. Native Codex provider and SDK failures retain only that classification and discard the provider message, while Harness-owned `LlmError` failures retain their code and message. Unrelated pi-ai routes keep their existing error text because this feature does not change their privacy policy. Missing, revoked, and refresh-failure Codex states bypass this path through `OAUTH_RECONNECT_REQUIRED`.

## Verification

Credential and pi-ai package suites pin private atomic mutation, generation-scoped writes, stale-request, stale-logout, and revoked-credential takeover races, peer-process private invalidation, device-code-only interaction, disposal, profile-driven public registration independent of OAuth status, a failed durable reconnect marker that leaves the published connection state unchanged, Harness-owned `LlmError` preservation, external provider and SDK exception redaction, and the explicit legacy-key distinction. Host and connection tests pin public provider and model topology across private status changes, trusted remote catalog access, and loopback-only lifecycle replies; client tests pin the local OAuth-status join and terminal disconnect-before-delete ordering. Loader composition proves a saved connection works through the shipped Headless profile without starting login. The keyless assembled Web scenario observes its model group before OAuth completion, then makes a real failing Codex request and proves its hostile sentinel is absent from stream events, durable persistence, browser history and events, Host and browser logs, visible copy, and the golden. The opt-in personal-subscription smoke retains credentials only in process memory, disconnects after a redacted `checkAuth()` and catalog check, and self-skips unless explicitly enabled.
